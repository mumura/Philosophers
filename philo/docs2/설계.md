# 관리자 시간 안내 설계 · 개요

- 상태: 부분 구현. 평가한 `adaptive`를 프로젝트에 적용. 현재 생각 시간 계약은 [adaptive](adaptive.md) 참조. 1~3단계 공통 계약과 목표 종료 보완을 적용·검증. 보류 실험과 전체 입력의 동작 보장까지 완료한 것은 아님.
- 목적: 정확한 식사·수면·사망 처리를 유지하면서 불필요한 기상·상태 확인·반복 동적 할당을 줄여 CPU 사용량 개선.
- 시간 안내 기준: 가장 이른 사망 예정 시간(가장 오래 갱신되지 않은 기록). 후보의 마지막 실제 식사 시작 시각 + `time_to_die`로 계산.

## 읽는 순서와 문서 역할

1. 이 문서에서 구현 범위 확인.
2. [상세 계약](포크대기%20설계.md)의 확정 계약·현재 구현과의 차이·검증 기준 확인.
3. 실제 헤더·정의·호출부와 대조한 변경안을 작성하고, 사용자 승인 범위에서 구현.

## 확정 범위

| 대상 | 확정 방향 | 상세 |
|---|---|---|
| 역할 | 관리자 함수가 시간·상태 판단, 철학자는 호출·대기·행동 보고, 메인 모니터가 사망 확정 | 상세 계약 1 |
| 실행 | 기존 포크 획득·반환과 1명 처리를 유지하며 공통 대기 흐름 교체 | 상세 계약 2 |
| 시간 | 행동 종료 시각 보존, 행동 종료와 후보 사망 판단 시각 중 빠른 시각까지 대기 후 재문의 | 상세 계약 3 |
| 식사 기록·감시 | `last_meal` 덮어쓰기, 최장 미갱신 후보 하나 유지, 후보 갱신 때만 전체 순회 | 상세 계약 4 |
| 잠금·출력 | 상태·출력 잠금 분리, 출력 → 상태 잠금 순서, 사망 로그 이후 일반 로그 차단 | 상세 계약 5 |
| 종료·정리 | 같은 판정 시점에는 사망 우선, 기존 재귀 초기화·역순 정리 유지 | 상세 계약 6 |

## 보류 범위 · 구현 대상 아님

- 공정한 요청 순서·두 포크 예약·식사 허가: 원칙만 기록. 저장·등록·허가·취소의 구체적 정책은 후속 논의.
- 포크 관리 시간 배열을 이용한 엇박 유도: 유지·변경·제거와 계산식·재문의 간격은 후속 논의.
- 실험안: 관리자가 여유 있는 철학자의 생각 시간을 제한적으로 늘려, 더 급하고 획득을 기다리는 이웃에게 기회를 유도. 계산 후보·필요한 상태·검증 조건은 상세 계약 C.1에 기록. 기아 방지 보장은 목표에서 제외하고, 예약·강제 차례 없이 별도 검증.
- 공통 계약 구현을 이유로 위 기능을 추가하거나 기존 엇박 배열을 임의로 삭제·변경하지 않음.
- 이 보류 때문에 공통 대기가 식사 기회·기아 방지를 보장한다고 해석하지 않음.

## 구현·검증 원칙

- 확정 계약을 단계별로 적용·검증. 우선 시간 기준과 관리자 호출 반복, 이후 후보 관리·잠금 변경을 별도 변경 단위로 검토.
- 식사 요청 큐·별도 시간 배정 스레드·로그 스레드·로그 큐는 확정 범위에 포함하지 않음.
- 함수명·반환 형식·시각 전달 단위·오류 전달은 구현안에서 명시. 확정된 역할·잠금 순서·완료 기준은 유지.
- 성능 개선은 같은 조건의 CPU 시간·기상 횟수와 정확성 지표를 비교해 판단. 미실행 결과를 개선으로 표시하지 않음.

## 구현 진행

- 1단계 완료: `state.oldest`로 후보 하나 보관, `last_meal` 덮어쓰기, 후보 갱신 시에만 재선정. 식사 기록 큐·감시용 `version`·식사별 기록 할당 제거.
- 기존 재귀 자원 관리 유지. 포크 획득 순서·생각 시간 계산·worker 반복·대기 함수는 변경하지 않음.
- 2단계 완료: 식사·수면의 고정 종료 시각, `wait_until()`의 관리자 계산 → `usleep` → 재계산 반복, 후보 사망 시각 기준 분할.
- 목표 종료 보완: 첫 목표 횟수 완료로 `full_count > 0`이 되면 이후 대기 할당을 최대 10ms로 제한. 그전과 목표 횟수 없는 실행은 기존 대기 정책 유지. 전체 목표 완료·식사 집계 의미는 바꾸지 않음.
- 3단계 완료: 출력/상태 잠금 분리, 출력 → 상태 순서, 최신 상태로 사망 확정 후 상태 잠금 없이 출력, 사망 우선 판정. 출력 뮤텍스 초기화·정리도 기존 재귀 흐름에 연결.
- 단계별 검증·CPU 비교·종료 반응 제한은 상세 계약 D 참조. 성능 결과는 측정 조건에 한정하며 기아 해결은 확인하지 않음. 예약은 보류. 이후 채택한 생각 시간 정책은 아래 현재 적용 버전 참조.

- C.1 과거 탐색 기록: 초기 WAITING 전용 양보는 개선 미확인. 관리자 배정 생각 종료 시각을 함께 보는 후속 후보는 시험 조건에서 완료 횟수 개선 관측. 당시에는 임시 복사본 실험으로 미채택. 이후 사용자 승인으로 적용한 현재 버전은 [adaptive](adaptive.md) 참조. 상세 계약 D의 진단/후속 후보 기록 참조.

## 현재 적용 버전

- `adaptive`: 초기 배치 분산 + 이후 관리자 배정 시각 보정. seed_only 및 과거 precheck 후보와 구분.
- 보류/미채택 항목 중 채택한 범위는 [현재 계약](adaptive.md)으로 대체. 예약·강제 차례는 계속 미도입.
