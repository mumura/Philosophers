**현재 설계는 ‘철학자는 실제 행동·식사 기록을 담당하고, 모니터는 갱신 큐로 사망을 감시하는 구조’야.** 엇박 조절은 포크 경쟁을 줄이기 위한 보완이야.

| 부분 | 현재 설계 |
|---|---|
| 자원 관리 | 기존 재귀 초기화·역순 정리 유지 |
| 철학자 | 철학자마다 스레드 하나 |
| 포크 | 양옆 포크를 각각 뮤텍스로 보호 |
| 식사 기록 | 실제로 두 포크를 확보하고 식사를 시작할 때 갱신 |
| 사망 감시 | 모니터가 기록과 현재 시각으로 판정 |
| 경쟁 완화 | 시작 시차와 매 주기 생각 대기로 엇박 유도 |
| 종료 | 전체 종료 기록 → 포크 반환 → 스레드 반환 → `join` → 자원 정리 |

**철학자의 실행 흐름**

1. 시작 시차 적용.
2. 정해진 획득 순서로 양옆 포크 확보.
3. 종료·자기 사망 조건을 상태 잠금 안에서 먼저 확인하고, 식사 시작 기록 갱신.
4. 갱신 큐에 기록 추가 → 식사 로그 → 식사 시간 대기.
5. 식사를 정상 완료하면 횟수 반영·포크 반환.
6. 수면 → 생각 로그·완충 대기 → 반복.

포크 획득 순서는 통일해 데드락을 예방하고, **1명일 때는 별도로 처리**해.

**갱신 큐와 모니터**

- 처음에는 모든 철학자의 시작 기록을 큐에 넣어.
- 식사를 시작하면 `{번호, 시작 시각, 갱신 번호}` 기록을 뒤에 추가해.
- 기록 갱신과 큐 추가는 같은 잠금 안에서 처리해 순서를 유지해.
- 모니터는 큐 앞에서 **이미 갱신된 옛 기록을 pop**해.
- 처음 남은 유효 기록이 가장 오래 식사하지 않은 철학자야.
- 그 기록의 **식사 시작 시각 + `time_to_die`**까지 기다려.
- 깨어나 최신 기록을 확인하고, 사망이면 종료 확정·출력, 갱신됐다면 다음 유효 기록으로 진행해.

**정렬·철학자 전체 순회 대신 기록을 순서대로 처리하며, 기록당 평균 처리 비용은 O(1)이야.**

**대기와 엇박 조절**

식사·수면 대기는 **실제 현재 시각으로 완료 여부를 판단**해. 사망 감시는 모니터가 독립적으로 하므로, 모든 철학자를 공통 사망 예정 시각마다 깨울 필요는 없어. 중간 종료 확인은 포크 반환·스레드 회수를 빠르게 하기 위한 선택이야.

생각 대기는 **이웃과 포크 경쟁을 줄이는 완충 시간**으로 사용해. 정확한 엇박을 보장하는 기능은 아니며, **시간 계산 기준과 감시자의 배정 여부는 아직 확정되지 않았어.**

**종료 규칙**

- 사망 정보는 모니터가 관리하고, 철학자는 **실행을 계속해도 되는지**만 확인.
- 사망 조건에 도달한 기록은 식사 갱신으로 되살리지 않음.
- 사망 출력은 한 번만, 이후 일반 행동 로그 차단.
- 종료해도 확보한 포크 반환은 허용.
- 식사 목표는 전체 완료 인원을 세어 달성 시 종료.

**남은 구현 결정은 큐의 저장·회수 방식, 생각 대기 계산, 종료 후 회수 속도를 위한 대기 분할 여부야.** 앞서 이야기한 기능을 모두 추가하는 게 아니라, 이 세 부분만 정하면 현재 설계의 뼈대가 완성돼.
