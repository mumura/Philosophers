**지금 설계는 ‘큐 기반 사망 감시’와 ‘주변 포크 상태에 따른 생각 대기’를 분리한 구조야.** 기존 재귀 자원 관리는 유지해.

| 구성 | 역할 |
|---|---|
| 철학자 스레드 | 포크 획득·식사·수면·생각 반복 |
| 포크별 뮤텍스 | 포크 중복 사용 방지 |
| 관리용 배열 | 포크 사용 여부·소유자, 실제 식사 시작 시각 저장 |
| 공용 관리 함수 | 호출한 철학자의 양옆 상태로 생각 대기 계산 |
| 갱신 기록 큐 | 식사 시작 기록을 시간순으로 저장 |
| 모니터 | 큐로 가장 이른 사망 후보를 찾아 판정·종료 |

**① 철학자의 행동 흐름**

**포크 획득 → 식사 시작 기록·큐 추가 → 식사 → 포크 반환 → 수면 → 생각 로그·계산된 대기 → 반복**

- 실제로 두 포크를 확보한 뒤 식사 시작 시각을 갱신해.
- 정상적으로 식사를 마쳤을 때 식사 횟수를 올려.
- 포크 획득 순서를 통일해 데드락을 예방해.
- 1명일 때는 별도로 처리해.

**② 생각 대기 계산**

철학자가 진입하면 **공용 함수가 그 순간의 양옆 포크 기록을 읽어, 그 철학자의 대기 시간만 계산**해.

> **예상 반납 시각 = 소유자의 실제 식사 시작 시각 + 식사 시간**
> **생각 대기 = 양쪽 예상 반납 중 늦은 시각 − 현재 시각**

- 둘 다 비어 있으면 바로 획득 시도.
- 소유자가 식사 중이면 남은 시간으로 계산.
- 소유자가 두 번째 포크를 기다리는 중이면 반납 시각을 예측할 수 없으므로 별도 재시도 규칙 적용.
- 계산 후 관리 잠금을 풀고 대기해.
- 깨어나면 최신 상태로 재확인해.

**양옆의 양옆까지 미래를 계산하지 않아.** 실제 행동의 영향은 각자가 다음 조회 때 반영해. 대기 배정은 예약이 아니므로 획득 경쟁은 남아.

공용 함수는 **호출한 철학자 스레드에서 실행**되고, 별도 관리자 스레드는 필요 없어.

**③ 큐 기반 사망 감시**

1. 처음에는 모든 철학자의 시작 기록을 큐에 넣어.
2. 식사 시작 때 최신 기록 갱신과 큐 추가를 같은 잠금 안에서 처리해.
3. 모니터는 큐 앞의 갱신된 옛 기록을 제거해.
4. 첫 유효 기록으로 다음 사망 시각을 계산해.
5. 잠금을 풀고 그 시각까지 모니터가 잠.
6. 깨어나 최신 기록으로 다시 판단해.

**사망 예정 시각 = 마지막 식사 시작 + `time_to_die`**

식사 갱신은 예정 시각을 뒤로만 미루므로, 모니터를 갱신마다 깨울 필요는 없어. 정렬·철학자 전체 순회 대신 **기록당 평균 O(1)**로 처리하는 방식이야.

**④ 종료와 정리**

- 모니터가 실제 사망을 확정하고 종료 상태·사망 출력을 처리해.
- 철학자의 사망 신호나 동의는 필요 없어.
- 식사 갱신과 사망 판정은 동기화해서 만료된 기록이 되살아나지 않게 해.
- 일반 로그와 사망 출력도 동기화해 종료 후 행동 출력을 막아.
- 철학자는 실행 허용 여부를 확인하고 확보한 포크를 반환해.
- 모두 `join`한 뒤 기존 재귀 흐름으로 역순 정리해.
- 식사 목표 달성도 전체 종료 사유로 처리해.

**식사·수면을 공통 사망 시각마다 잘라 깨우는 기능은 필수가 아니야.** 중간에 종료를 확인하도록 나눠 자는 것은 빠른 포크 반환·회수를 위한 선택으로 남겨둬.

남은 결정은 **큐 저장·회수 방식, 반납 시각을 예측할 수 없을 때의 재시도 규칙, 종료 확인 간격**이야. 생각 대기는 경쟁 완화용이며, 정확한 엇박이나 공정성을 보장하는 장치는 아니야.
